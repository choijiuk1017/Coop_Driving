# 인게임 기믹

## 상속 구조와 공통 처리

```text
AGimmick (추상 AActor)
 ├─ ACargoSpeedBump        기존 클래스/경로 유지
 ├─ ADeerGimmick
 ├─ ATrafficLightGimmick
 └─ APoliceGimmick        경찰/단속반은 같은 클래스의 BP 변형으로 사용
```

`AGimmick`은 활성화 상태(`bActive`), 내장 접근 영역, 대상 차량(`TargetVehicle`), 복제, 충돌 이벤트 연결 및 효과 알림을 관리한다. 차량을 비워 두면 `DrivingGameMode`의 공용 차량을 자동으로 사용한다. 운전 GameMode가 없는 테스트 맵에서는 배치된 첫 `CoopVehicle`을 자동 탐색하여 캐시한다. 아직 차량이 없으면 0.5초 간격으로 재시도하므로 나중에 스폰되는 차량도 찾는다. 여러 차량 중 특정 차량을 대상으로 할 때만 **Target Vehicle**을 지정한다.

- **Set Gimmick Active**: 서버에서 활성화/비활성화한다. 재활성화 시 각 기믹의 관측/추격 상태를 초기화한다. `Vehicle Approach` 모드는 활성화 후 차량 접근을 기다린다.
- **Activation Mode**: `Immediate`는 즉시 동작, `Vehicle Approach`는 내장 **ActivationZone**에 차량이 진입할 때 시작한다. 기본값은 방지턱·신호등이 Immediate, 고라니·경찰이 Vehicle Approach다. 접근 판정은 차량 원점과 이동 선분을 사용하므로 Overlap 설정이나 외부 트리거 BP가 필요 없다. 고속으로 영역을 건너뛰는 차량도 검사한다.
- `UpdateGimmick`: 활성화된 동안 서버에서만 실행하는 가상 함수.
- `OnActivationChanged`: 활성화 변경 시 서버와 클라이언트의 표현·충돌 상태를 갱신하는 가상 함수.
- `OnVehicleHit`: 공용/지정 차량과의 충돌만 서버에서 전달하는 가상 함수.
- `ApplyEffect`: 각 하위 클래스가 실제 효과를 구현하는 가상 함수. 부모 호출 시 서버 C++ 델리게이트 `OnEffectApplied`, 서버 BP 이벤트 **Apply Gimmick Effect**, 전체 피어의 연출 BP 이벤트 **On Gimmick Triggered**를 알린다. 재화·화물 변경은 서버 이벤트에만 연결한다.

공통 함수는 RPC가 아니다. 별도 UI에서 수동 제어할 때만 소유 PlayerController의 서버 RPC를 거쳐 호출한다. 기본 배치 동작에는 BP 호출이 필요 없다. 이동, 활성화, 접근 대기, 신호 상태, 경찰 검거 결과, 차량 운전 금지는 복제된다.

## 에디터 설정

새 부모/반영 속성이 추가되었으므로 작업을 저장하고 에디터를 재시작하여 새 모듈을 로드한다. **각 클래스를 레벨에 드래그해 위치·회전을 정하고 Play하면 기본 기능이 작동한다.** 별도 스폰 코드, 레벨 BP, 트리거 액터, 차량 참조 연결은 필요 없다. 고라니·경찰을 여러 구간에 복사해서 배치하면 각 인스턴스가 자기 구간의 접근을 기다린다.

청록색 **DirectionArrow**는 로컬 +X를 표시한다. 고라니는 횡단 방향, 신호등은 차량 통과 방향으로 맞춘다. 고라니·경찰은 선택 후 **ActivationZone → Box Extent**로 출현 구역을 조절한다. 기본 반경은 X/Y 1800cm, Z 400cm이며, 기본 도형의 비균일 스케일에 영향을 받지 않는다. 영역의 위치·회전·크기는 해당 컴포넌트에서 조절한다. 접근 전에는 몸체가 숨겨지고 충돌/고라니 중력이 꺼져 있어, 차량이 멀리 있어도 먼저 이동하거나 사라지지 않는다.

코드에서는 저장된 맵이나 기존 BP 에셋을 변경하지 않았다. 기본 도형은 기능 확인용이며, 고라니/경찰 외형과 신호등 메시·발광 머티리얼은 BP에서 교체할 수 있다. 정상 인게임의 차량 조작과 라운드 흐름은 기존 DrivingGameMode를 사용한다.

### 방지턱: Cargo Speed Bump

- 기존 `Vehicle/CargoSpeedBump` 클래스를 그대로 사용한다. `Surface`의 둥근 윗부분이 노출되도록 원점을 노면에 배치하고, 액터 +X를 도로 진행 방향으로 맞춘다.
- 현재 Chaos 차량·바퀴와 물리 화물이 충격을 전달하므로 추가 임펄스나 강제 화물 감소는 넣지 않았다. 고속 주행에 따른 충격/낙하는 기존 물리 설정의 결과다.
- 비활성화하면 충돌을 끈다. 기본 차량의 **Cargo → Test → Spawn Test Speed Bump**는 기존처럼 시험용 방지턱을 생성하므로, 맵에 직접 배치할 때 필요에 따라 해제한다.

### 고라니: Deer Gimmick

- 길 가장자리에 **Body가 지면에 파묻히지 않게** 배치하고 액터 +X를 횡단 방향으로 회전한다. 기본 Body는 물리 충돌이 있는 큐브다. 교체 메시에도 단순 충돌이 있어야 한다.
- **Crossing Speed**(기본 900cm/s), **Crossing Distance**(2500cm), **Mass Kg**(70kg)를 설정한다. 중력과 CCD를 사용하는 물리 몸체로 횡단한다.
- 대상 차량과 첫 충돌 시 효과 이벤트를 한 번 발생시키고, 현재 물리 접촉이 처리되도록 0.05초 뒤 서버에서 제거한다. 별도 충격을 덧붙이지 않는다. 여러 메시/접촉의 중복 콜백도 한 번만 소비한다.
- 기본값 그대로 배치하면 차량이 내장 ActivationZone에 접근할 때 나타나서 횡단한다. 횡단을 마치거나 **횡단 시작 후** 이동시간+5초가 지나면 제거한다. 즉시 횡단하는 연출이 필요할 때만 Activation Mode를 Immediate로 바꾼다.

### 신호등: Traffic Light Gimmick

- **StopZone의 로컬 X=0 평면이 정지선**이다. 차량이 로컬 X 음수에서 양수로 주행하도록 배치한다. 다른 방향/차선에는 별도의 기믹을 사용한다.
- StopZone의 Y 반경은 차선 폭, Z 반경은 차량 높이 판정 범위, X 음수 쪽은 정차 감지 거리다. 기본 ±600/±600/±300cm이며 회전·크기 조절이 가능하다. 차량 **원점** 기준 판정이다.
- 서버가 이전·현재 위치 선분과 정지선의 교차를 계산한다. 고속으로 한 프레임에 영역 전체를 지나도 검사하며, 반대 방향·옆 차선·고가도로는 제외한다. 배치/재활성화 시 이미 선을 지난 차량은 위반으로 처리하지 않는다.
- 기본 주기: 빨강 8초 → 초록 8초 → 노랑 2초 → 빨강. **Automatic Cycle**을 끄고 서버 **Set Signal**로 직접 제어할 수도 있다. 노랑은 기본적으로 통과 허용이며 **Treat Yellow As Red**로 변경한다.
- 빨강 접근 구역에서 속도 10cm/s 이하로 0.5초 정차하면 서버 **On Vehicle Stopped** 이벤트가 발생한다. 초록 출발/통과는 허용하고 빨강 정지선 통과만 위반으로 판정한다. 차량에 자동 운전 입력을 주지 않는다.
- 위반 시 효과 이벤트와 로그만 발생한다. 요청에 따라 `ApplyEffect`의 화물/재화 감소 예시는 **주석 처리**했다. 현재 프로젝트에는 수량 기반 화물 인벤토리나 지갑 API가 없으므로 예시 이름은 실제 API가 아니다.
- 기본 PointLight 세 개는 신호 상태에 맞춰 켜진다. 완성 외형은 BP에서 추가한다.

### 경찰/단속반: Police Gimmick

- **추격을 발생시킬 도로 구간에 배치**하면 내장 ActivationZone에서 차량을 기다린다. 차량이 접근하면 그 뒤 1800cm에 나타나 추격을 시작한다. 별도 접근 트리거는 필요 없다. **Start Behind Vehicle**을 끄면 배치한 위치에서 출발한다. 레벨 시작 즉시 추격하려면 Activation Mode를 Immediate로 바꾼다.
- 기본 **Pursuit Duration** 15초, **Pursuit Speed** 1800cm/s, **Catch Distance** 500cm다. 추격이 시작된 후에만 시간이 흐른다. 시간 안에 거리 안으로 들어오거나 차량과 충돌하면 한 번 검거한다. 시간이 만료되면 패널티 없이 비활성화하고 충돌을 끈다. 다시 활성화하면 새로운 추격이다.
- 추격은 차량 현재 위치를 향하는 직접 이동과 정적 노면 높이 보정, 장애물 sweep을 사용한다. 복잡한 커브·교차로·장애물 우회는 도로 경로/AI 주행을 추가해야 한다.
- **Game Over On Catch=true**면 `DrivingGameMode::TryFailDriving`을 호출한다. 공용 차량의 가속/조향/변속을 막고 브레이크·핸드브레이크를 적용하며, 목적지 도착 성공도 차단한다. 차량의 복제 상태를 통해 기존 HUD에 **GAME OVER**를 표시한다. 운전 GameMode가 없는 차량 시험 맵에서도 검거 시 차량 운전을 막는다.
- 서버 GameMode BP의 **On Driving Failed**에서 결과 UI나 로비 복귀를 연결한다. 기본 구현은 실패 상태에서 멈추며 자동 재시작/로비 이동은 하지 않는다.
- **Game Over On Catch=false**면 서버 **Apply Gimmick Effect** 이벤트에 수량/재화 패널티를 연결할 수 있다. C++에도 주석 예시를 남겼다. 경찰과 단속반은 BP 외형과 이 옵션을 다르게 설정하여 사용한다.

## 검증

2026-11-19: UHT/C++ 컴파일과 Editor 모듈(`2173`) 링크를 통과했다. 실행 중인 기존 에디터가 DLL을 사용하고 있어 별도 이름으로 빌드했으며 에디터를 재시작하면 새 모듈을 사용한다. 전체 `CoopDriving` 자동 테스트 **13개(기믹 6개 + 기존 7개) 모두 통과**, 실패/미실행 0개다. 특히 레벨 시작 전에 네 종류를 배치하고 아무 참조/이벤트를 연결하지 않은 상태의 자동 동작을 운전 GameMode 사용/미사용 두 환경에서 확인했다. 결과는 `Saved/Automation/Gimmicks/index.json`, 실행 로그는 `Saved/Logs/GimmickTests.log`에 있다. 시험용 기본 차량의 토크 커브 누락 등 경고가 포함되어 있으며, 실제 차량 BP를 사용한 4인 PIE 물리·복제 검증은 수행하지 않았다.

`CoopDriving.Gimmick` 자동 테스트는 회전/스케일된 정지선, 고속/역방향/차선 밖 통과, 빨강/초록/노랑 규칙, 재활성화, 고라니 중복 접촉, 방지턱 활성화 충돌, 경찰 검거/시간 만료, 실패 후 입력 차단을 검사한다. `PlacedActorsWorkWithoutWiring`은 네 종류를 BeginPlay 전에 배치하고, 차량 참조나 BP 호출 없이 원거리 대기 → 접근 → 기본 효과까지 검사한다. DrivingGameMode 사용/미사용 두 환경과 복사한 고라니의 고속 접근도 포함한다. 이 테스트의 고라니 접촉은 콜백을 주입하므로 실제 차량/화물 충격량은 PIE에서 확인한다.

수동 확인은 운전 맵의 서버·클라이언트에서 진행한다.

1. 방지턱을 저속/고속으로 넘어 차량과 화물의 물리 충격을 비교한다.
2. 고라니를 길가에 배치하고 차량으로 접근하여 자동 출현/도로 횡단, 첫 충돌 후 제거, 클라이언트의 제거/충격 동기화를 확인한다.
3. 빨강에서 정차한 뒤 초록에 출발하고, 빨강 통과 시에만 위반 이벤트가 발생하는지 확인한다.
4. 경찰에게 잡히면 모든 클라이언트 HUD와 입력이 실패 상태가 되는지, 15초를 버티면 패널티가 없는지 확인한다.
5. 사용자 제작 외형/도로 크기에 맞춰 충돌체, 정지선, 질량, 추격 수치를 조정한다.
